# Active synthetic scheduler I/O ABI review

The bounded x86-64 probe uses the pinned Microsoft WSL kernel revision `d504d40ab83839cb61942a812a99d183c42227b9`. Source shows `BPF_F_RDONLY` and `BPF_F_WRONLY` select the created descriptor's userspace access mode. A normal array supports these flags and zero-initializes its elements. The private state descriptor is write-only, with no element-read entry point in the driver. Counts and rows use read-only descriptors. Program access flags are distinct. A descriptor flag alone is no isolation guarantee against a privileged kernel observer. [UAPI flags](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/uapi/linux/bpf.h#L1386-L1403) · [Array map allocation](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/arraymap.c#L49-L139) · [Descriptor access enforcement](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/syscall.c#L1183-L1205)

`BPF_RAW_TRACEPOINT_OPEN` uses the 24-byte `name/prog_fd/pad/cookie` prefix with zero pad and cookie. The legacy raw tracepoint link reports exact `tp_name` and `cookie` in its fdinfo. The probe accepts only the reviewed names. Raw link release unregisters the tracepoint callback. The release call itself does not establish that a callback already in flight has ended. [Attach UAPI](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/uapi/linux/bpf.h#L1721-L1726) · [Release and fdinfo](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/syscall.c#L3786-L3813)

`BPF_OBJ_GET_INFO_BY_FD` returns the requested 216-byte prefix through `recursion_misses` for the owned raw tracepoint program. The retained, hash-pinned vmlinux BTF independently gives `bpf_prog_info` size 232 and unsigned eight-byte `recursion_misses` offset 208. The counter tracks kernel suppression on per-program recursion paths. It is distinct from runtime counters and the sink's attempted/failed accounting. Only the selected counter is read by the Python caller. [Program info UAPI](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/uapi/linux/bpf.h#L6626-L6667) · [Raw trace recursion suppression](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/trace/bpf_trace.c#L2059-L2070)

Windows and WSL each passed eight tests with a mocked BPF syscall. The tests cover exact map, lookup, attach and program-info attributes, invalid hook/index rejection, link fdinfo validation, kernel error propagation and missing-counter rejection. Native I/O remains for the root operator's separately frozen run.
