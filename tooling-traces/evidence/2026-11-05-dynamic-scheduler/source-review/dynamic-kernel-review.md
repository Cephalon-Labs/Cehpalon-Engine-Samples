## Birth and namespace identity

`copy_process` rejects `CLONE_THREAD` with new PID/user namespaces or a changed PID namespace for children. It sets the new task's initial-namespace PID, TGID and leader, initializes its start-boottime, assigns `thread_pid`, and attaches the PID before `trace_task_newtask(task, u64 clone_flags)`. In `kernel_clone`, the successful return is followed by `trace_sched_process_fork(current,p)` and then `wake_up_new_task(p)`. The latter enqueues and traces `sched_wakeup_new(p)` under runqueue lock before wakeup preemption. This provides a synchronous admission point before first wake for an ordinary thread created by an already admitted task. The kernel may publish the PID before the admission point. The source does not prove that every possible observation of the task happens after admission. [Fork](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/fork.c#L1980-L1990) · [Birth trace prototype](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/events/task.h#L9-L29) · [First wake](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/sched/core.c#L4824-L4867)

A positive admission requires a verified active parent generation, `CLONE_THREAD`, the leased initial-namespace TGID, and a checked birth identity. Use live BTF and guarded reads to cross-check `task->pid` against `thread_pid->numbers[0].nr`, and bind the local TID via `numbers[level].nr`. Require level within 0–32, positive IDs and the same seed namespace pointer and inode. Cache IDs during admission. `numbers[]` is a flexible array whose allocation provides the entries through `level`. Confirm the held leader's observed gettid and PID namespace against the kernel seed. `bpf_get_ns_current_pid_tgid` can corroborate current's seed after matching namespace device/inode. It cannot read the namespace IDs of a remote tracepoint target. `/proc` start ticks are a separate lease observation. [PID allocation and namespace conversion](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/pid.c#L162-L290) · [PID layout](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/linux/pid.h#L47-L69) · [Depth bound](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/linux/pid_namespace.h#L14-L15) · [Current-only helper](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/helpers.c#L589-L627)

Exclude process-fork children even if their parents are owned. A bounded kernel map with no LRU or silent eviction can bind pointer plus checked own start-boottime to the cached generation and IDs. Kernel addresses stay internal and the collector reads no pointer-key map entries. Treat an owned-path field read failure, reuse/collision, unknown same-group target, duplicate admission or map exhaustion as a failed epoch. Keep seed, birth and output validation distinct. No retrospective learning from observed TIDs, proc polling, or a leader-pointer comparison. A write-only map FD can deny collector lookup and get-next-key calls; it does not make the map inaccessible to a privileged party.

## Owner seed and attachment

Userspace task-storage update uses a pidfd integer key, takes a PID-object reference, and resolves `PIDTYPE_PID` under RCU. Missing tasks fail. This supports binding one pre-existing held ordinary leader, rather than trusting a sampled TGID or holding a numeric ID indefinitely. A task storage map requires `BPF_F_NO_PREALLOC`, zero `max_entries`, integer key and supplied key/value BTF IDs. Its map-create path requires userspace BTF. Limit this map to the seed and omit implicit cloning. Legacy raw-tracepoint context accesses expose scalar argument slots, while the task-storage helper requires a typed task pointer. The tracing/base helper tables expose `bpf_get_current_task_btf` and task storage; using the typed current helper to confirm the seeded live owner is a source-supported candidate. Loading it with an exact typed-current helper sequence remains a verifier test. Reading target pointers as raw scalars for verified offset reads is a separate verifier test. A `tp_btf` candidate would need correct attach BTF IDs and independently verified argument typing and helper behavior. [Task storage update and helper types](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/bpf_task_storage.c#L119-L155) · [Map allocation checks](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/bpf/bpf_local_storage.c#L704-L718) · [Raw context and verifier](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/trace/bpf_trace.c#L1669-L1781)

If later needed, an explicitly frozen seed alternative is an owner-triggered native x86-64 gettid while an ordinary, single-threaded, leased owner stays alive and unreaped. Filter the raw `sys_enter(regs,id)` path for the reviewed native syscall and kernel-bound owner identity before any field read. The per-task perf gettid event from ADR0028 can independently corroborate the mapping, while a raw BPF hook is invoked across the guest. The perf BPF trace program array runs before eventual perf delivery and filters, so a task-scoped perf FD cannot itself scope BPF execution. A failed pidfd preflight does not authorize silently switching seed modes. ## Remote selection and teardown

Select `prev` and `next` from raw switch arguments `(preempt,prev,next,prev_state)`. The switch-in target can be owned when the callback's current is unowned. Waking, wakeup and new-wake each provide target `p`; migration provides `(p,dest_cpu)`; fork provides `(parent,child)`; exit provides `(p,group_dead)`; free provides `(p)`. Source marks waking as waking-context and wakeup as possibly elsewhere. Retain emitter CPU independently from target CPU. In this x86-64 SMP build with `THREAD_INFO_IN_TASK`, reading normalized target/original CPU semantics from raw callbacks requires separately checking embedded `task_struct.thread_info` and `thread_info.cpu` in live BTF, or an independently associated CPU oracle. The raw callback does not pass the normalized target/original CPU field. At waking it can still be the pre-selection CPU. A credible remote positive case records a target wake request from a controlled CPU distinct from the target's CPU with a nonmember source, then follows the actual owned target's wake and switch. Keep foreign identities, addresses, comm and stacks out of output. A guest-wide hook transiently observes task argument pointers and minimal rejection information. This scope is broader than its retained output. [Tracepoint arguments and normalized fields](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/events/sched.h#L139-L290) · [CPU source](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/include/linux/sched.h#L2237-L2244)

Exit announces `group_dead` based on the live-thread counter and precedes the final scheduler switch. The raw switch sees kernel `prev_state`, separate from the normalized state/preempt representation. `do_task_dead` sets `TASK_DEAD`; final switch cleanup drops one RCU user reference. Process release detaches PIDs and drops the other RCU user reference. Delayed RCU callback traces free before the final task reference put. Preserve a retired lifecycle state between exit and terminal switch/free. The callback's own task object remains available, but looking up its detached `thread_pid` or dereferencing its leader is outside this lifetime proof. Retain one terminal record using cached identity and then remove the live entry. Do not count post-exit records as active work. Stop admission when the owner exits or group-death is observed. Observe the declared RCU tail; a missing free remains incomplete. [Exit and free paths](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/exit.c#L227-L243) · [Terminal switch](https://github.com/microsoft/WSL2-Linux-Kernel/blob/d504d40ab83839cb61942a812a99d183c42227b9/kernel/sched/core.c#L5245-L5254)

De-thread during exec copies the former leader's start-boottime to the execing task, swaps TIDs and reassigns leaders. Use `sched_prepare_exec(task,bprm)` as the proposed pre-mutation owned-epoch veto and read no `bprm` fields. It occurs before de-thread and the subsequent fatal-on-failure path. `sched_process_exec` fires after successful transition. Declare the synthetic owner no-exec after its hold point and invalidate the complete epoch if the guard fires or required evidence is missing. A racing already-published row cannot rehabilitate an invalid epoch. ## Next bounded proof

Freeze a no-attach verifier/resource preflight first. Pin source, live BTF/hash/layouts, architecture, loader/syscall ABI, exact instruction bytes, map/resource limits, commands and private output. A minimal pidfd-seed candidate loads only its small key/value BTF, creates one task-storage map, and loads one inert program covering typed-current lookup, with no task-storage update, target, attach, ring or global state change. A separately frozen no-attach scalar-context/guarded-read/hash program would answer the distinct legacy raw target-access question. Capture exact verifier outcomes and close all FDs on every path. Neither pass establishes runtime hook delivery or readiness.

Next freeze a separate synthetic run with gate-closed attach, one held mapped ordinary owner, an explicit seed acknowledgement, a fresh post-release child thread, a controlled nonmember process and a short-lived owned child whose lifecycle does not rely on proc polling. Prove one positive birth→first wake→switch-in→exit→terminal switch-out→free and a controlled cross-CPU nonmember waking context without foreign records. Keep total attempt/submit/fail and terminal drain counters and explicit missing/duplicate data. Raw trace dispatch can skip recursion before a program sees the event.
