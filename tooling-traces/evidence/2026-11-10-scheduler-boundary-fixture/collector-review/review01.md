# Synthetic scheduler boundary collector design review

2026-11-10. Read-only implementation/adversarial review for Engine #20 / ADR0031. No actor, attach, BPF load, build, global configuration, remote mutation or program source edit was performed. The accompanying hashes identify the helper versions inspected, without an immutable execution claim. The new boundary implementation still needs a source review before root's native attempt.

## Reuse limits

`SchedulerSession.arm` is specifically a suspended CoreCLR lane: it requires the exact mapped libcoreclr and `verify_process` checks the native dotnet host. A Python synthetic actor needs a separately scoped resource/session wrapper; calling the class unchanged will reject it. `roslyn_program` hardcodes 262144 rows and 64 members, including the prearm admission path. Keep those physical bounds if directly reusing it, or introduce and test an explicit new parameterized builder. Do not silently describe smaller compiled bounds while using its unchanged template.

The existing lifecycle `target` reads raw argument0 as a task pointer for most hooks. For `sched_entry_tp` / `sched_exit_tp`, argument0 is a bool. A new boundary builder must obtain current task itself, do a private membership lookup, then validate TASK_BIRTH before emitting member identity. It can use typed-current storage to recognize a preseeded leader, but unseeded dynamic children require the existing owned-parent birth/membership path. Presence of a current-task pointer alone is not authority. Existing `get_member` validates birth but does not reject retired members; terminal behavior must be explicitly chosen.

The shared native I/O hook allowlist currently omits these two names. Extend exactly the two names and retain exact link fdinfo checks, or use a local wrapper restricted to those two names. Do not bypass validation with arbitrary raw hook names. A successful source/BTF inventory does not guarantee raw attachment. Retain verifier/attach failures and stop the lane without an unscoped fentry/perf fallback.

## Minimal safe dynamic scope

Use one held ordinary prearm leader and one controlled newborn worker, with exact pidfd lease, namespace/start-time/credentials/executable before/after checks and source-frozen actor. Bind the leader through the task-storage ACK; use prearm enrollment to create a private member generation before releasing work. Attach lifecycle birth/free and boundary hooks before enabling prearm membership. Hold the actor before any child creation. A fixed ordinary pipe-block/wake worker demonstrates that a child born from an authenticated parent is admitted before its first scheduling exit. Existing task_newtask guards already reject non-thread process fork and foreign TGID/namespace. Child membership must retain its generation and birth identity through free.

Keep boundary records separate from the unchanged legacy lifecycle ABI. Use kind, raw bool, current generation, local/global IDs, per-generation sequence and CPU/timestamp points. Never output private pointers. A per-generation atomic sequence is more useful for association than globally sorted helper5 timestamps, which remain conditional. Do not reuse the last four member-value bytes for a new semantic without explicit initialization and clear tests: prearm/birth initialize the whole 32-byte value, and free removes it. If new state is needed, prefer a separately bounded generation-indexed state map over silently changing the shared membership ABI.

Global emission order interleaves independent tasks. Pair entry and exit within one owned generation and scheduler invocation, never by CPU. A resumed task may return on another CPU. A leader's first observed exit can be an enrollment prefix. A newborn schedule_tail exit(true) can legitimately have no previous entry. Exit(false) is a no-switch result. A terminal do_exit scheduling entry may never return. Either skip retired members in the boundary hooks and document the intentionally excluded terminal phase, or account for an unreturned terminal invocation at retirement/free. Do not require every observed entry to have a returning exit regardless of lifecycle.

## Fixed controls and collection gates

Freeze a negative capacity-one boundary ledger followed by a fresh positive ledger. Keep the legacy lifecycle channel full-sized in both cases so the negative's intentional boundary loss does not erase the ownership proof. Native scheduler callback counts vary with shared-host activity: reconcile exact attempted/retained/lost/fault counters instead of demanding an invented constant boundary-event count. Require positive no-loss, full detached reads and hashes, zero unused slots, zero reported recursion misses, complete expected admission/exit/free and explicit close accounting. Bound capacities, total generations, work duration, tail and all owned resources in advance. Do not resize/drain or repeat unchanged work for a favorable result.

Before admission, owner scheduler activity must emit no boundary rows. Nonmember root and fork controls must leave the scoped member/row counters unchanged except for explicitly selected leader scheduler activity; if the leader itself blocks during a control, do not mistake that legitimate emission for a foreign-task leak. Source/identity-bound row checks are stronger than asserting every global counter remains zero after the leader is already admitted. Record controls at well-defined stages or use preadmission control gates.

Fixed sched_yield calls are a reasonable attempt to observe exit(false), but cannot guarantee a no-switch outcome on a shared host. Predeclare a finite count, preserve all actual booleans and report runtime false coverage if observed; if none occurs, keep it uncovered rather than rerunning. Separate offline explicit false-case/parser conformance from actual native false coverage. Avoid changing actor RT policy or global scheduling configuration merely to force a favorable sample.

For failure/timeout, detach new hooks before releasing map/program FDs, then stop/reap the owned actor and close streams/pidfds. Register each resource immediately after creation, including either successful first hook when the second attachment fails. A stale root process or inherited session is not authorization to close unrelated descriptors. Save partial stage reports and exact loaded bytecode/verifier output on every rejection. Expect increased FD accounting: two boundary programs, two links and separate counts/record maps add six native FDs to a directly reused legacy session; an extra invocation map adds one more. Compute against the actual wrapper rather than copying an old 28/29 count.

## Proof boundary

The new fixture can establish named hook attachment, scoped ownership, raw bool/current-invocation observations and correct newborn/no-switch handling in this controlled execution. Callback timestamps remain inner software observation points, not exact physical CPU dispatch/withdrawal. The previous clock brackets do not transfer to this or historical Roslyn executions. Keep physical CPU/blocked/runqueue durations, GC pauses/exclusive causes, speedup, general capture readiness and original benchmark qualification open. Keep #3's complete Blocked row and #20 metadata/gates/null hours unchanged, with root the sole native and remote operator.
