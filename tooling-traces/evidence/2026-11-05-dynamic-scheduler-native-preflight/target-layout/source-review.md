# Fixed raw target CPU verifier candidate

The retained BTF and WSL source agree on the layout for the reviewed x86-64 build. BTF identifies `task_struct` as type 184, size 3328. It embeds type 342 `thread_info` at offset 0 and size 24. The latter contains unsigned four-byte `cpu` at offset 20. The retained config has `CONFIG_THREAD_INFO_IN_TASK=y` and `CONFIG_SMP=y`. In the pinned WSL source those settings select the embedded field, and `task_cpu(p)` reads that CPU. [Task definition and task CPU access](https://raw.githubusercontent.com/microsoft/WSL2-Linux-Kernel/d504d40ab83839cb61942a812a99d183c42227b9/include/linux/sched.h), [x86 thread information](https://raw.githubusercontent.com/microsoft/WSL2-Linux-Kernel/d504d40ab83839cb61942a812a99d183c42227b9/arch/x86/include/asm/thread_info.h)

`sched_waking` has one declared argument, the target task pointer `p`. The raw BPF callback shim packs that argument into context slot 0. The separate callback bookkeeping argument is outside that slot array. The normalized tracepoint assignment for `target_cpu` reads `task_cpu(p)`. This is the scheduler's target task CPU field at the hook, with actual execution CPU and emitter CPU requiring separate evidence. [Wake tracepoint definition](https://raw.githubusercontent.com/microsoft/WSL2-Linux-Kernel/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/events/sched.h), [Raw BPF callback shim](https://raw.githubusercontent.com/microsoft/WSL2-Linux-Kernel/d504d40ab83839cb61942a812a99d183c42227b9/include/trace/bpf_probe.h)

The fixed eight-instruction probe takes slot 0 as a scalar, adds 20 and requests a guarded four-byte kernel read into stack scratch space. It discards the helper result and returns zero. The program is designed only to load unattached. The accepted-load criterion would cover the generic raw context access and helper argument sequence. Hook binding, CPU equality, runtime helper behavior and remote wake coverage require active synthetic evidence. The script has a distinct offline BTF mode and a single native `BPF_PROG_LOAD` command in load mode. The agent ran the offline mode and mocked tests only.

The prior untouched `preflight_scheduler_dynamic_verifier.py` supplies the host pin, UAPI constants and instruction encoder.
