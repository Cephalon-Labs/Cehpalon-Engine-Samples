# GC and native lifetime joins for the Roslyn lane

Review date 2026-11-07. Source revision is the installed .NET 11 RC3 VMR commit 5254d8bcf59917edc1e1abc33bdf2442b77b1c70. This review reads source and retained evidence and runs pure Python fixtures. Root owns any new native capture and remote writes.

The existing marker mapper in Samples tools/analyze_roslyn_task_lineage.py checks exact marker/sidecar fields and derives a Fraction interval d = EventPipe relative milliseconds minus Stopwatch milliseconds. It intersects the logging-call bounds from every marker. For an EventPipe point e and offset [low, high], the corresponding MONOTONIC interval is [(e-high)*1,000,000, (e-low)*1,000,000] nanoseconds. Keep the complete interval. The Linux runtime uses a 1 GHz Stopwatch and CLOCK_MONOTONIC on the reviewed path. Same-execution PID/time namespaces, zero monotonic offset, loaded runtime mapping and source/build provenance remain capture prerequisites. [Stopwatch](https://raw.githubusercontent.com/dotnet/dotnet/5254d8bcf59917edc1e1abc33bdf2442b77b1c70/src/runtime/src/libraries/System.Private.CoreLib/src/System/Diagnostics/Stopwatch.Unix.cs), [native clock](https://raw.githubusercontent.com/dotnet/dotnet/5254d8bcf59917edc1e1abc33bdf2442b77b1c70/src/runtime/src/native/minipal/time.c)

The pure scheduler_eventpipe_join utility accepts one explicitly execution-scoped native header and at most 64 owned generation records. It requires the whole mapped interval strictly inside a unique lifecycle phase before returning active or retired identity. Enrollment, exit and free boundaries stay unassigned. Clock intervals spanning reused numeric TIDs remain ambiguous. Missing lifecycle information stays explicit. For a pre-arm generation, born_ns denotes its enrollment boundary and initial_state_unknown=true marks a left-censored identity. The helper always returns scheduler_state=null. An active identity phase does not establish that the task was on CPU, runnable or blocked.

TPL start/end/wait points should each pass the same native lifetime check. A TPL task lifetime is process-scoped and may execute on the waiting caller via inlining. Native header identity is event-scoped. Store separate source indices and lifetime generation bindings for the start, completion, wait begin, wait end and sampled points. If one boundary is ambiguous, preserve the original query and its unknown binding. A thread's earlier Roslyn frame does not classify all of its later execution.

The retained GC review identified exact phase metadata. SuspendEEStart is ID9/opcode10/version1 with Reason, Count and ClrInstanceID. SuspendEEStop is ID8/opcode137/version1. RestartEEStart is ID7/opcode136/version1. RestartEEStop is ID3/opcode132/version1. The latter three carry ClrInstanceID only. Retain the raw provider, ID/opcode/version/template, ClrInstanceID, payload, native emitter TID and source index. The header chain records the emitting thread for ordinary GC events, which does not identify every stopped worker.

Existing GC envelope models remain uncertified. The exact source emits SuspendEEBegin before the ThreadStore lock at 5531/5550, unlocks before RestartEEEnd at 5454/5485, and has a debugger retry path through RestartEE(false) at 5685 followed by a jump back below the original begin. The reviewed GC bridge has synchronous selected call paths, while server/background modes, build macros and retry applicability still require case-specific source evidence. Both global-adjacency and blanket same-emitter four-phase pairing can misrepresent those paths. Preserve the legacy 23/21/83 interpretations as separate studies. [Exact suspension source](https://raw.githubusercontent.com/dotnet/dotnet/5254d8bcf59917edc1e1abc33bdf2442b77b1c70/src/runtime/src/coreclr/vm/threadsuspend.cpp)

For the next capture, report literal GC phase points and source-supported candidate intervals with their ambiguity and branch evidence. Retain malformed/retry/overlapping/incomplete episodes. A scheduler interval can co-occur with those observations, but adding or subtracting overlapping dimensions does not establish a GC share, scheduler share, starvation or avoidable Engine work. This helper calculates no GC pause total and makes no causal classification.

The isolated join implementation has twelve tests, passing on Windows Python 3.11.15 and Ubuntu WSL Python 3.10.12. Cases exercise exact Fraction conversion, active versus retired phase, enrollment/exit/free boundaries, numeric reuse, clock uncertainty across reuse, overlapping lifetimes, left-censored pre-arm records, missing endpoints, foreign process, cross-execution records, invalid clocks and the 64-generation bound.
