# CLR ThreadPool boundary hooks and incremental overhead

Date 2026-11-15. ADR0031 and Engine #20. Reuse the exact retained CLR fixture and pinned WSL kernel, BTF, host and runtime from ADR0030. Each fresh ordinary process uses the original 64 pipe round trips and checksum. Both modes run the original nine-hook lifecycle collector. The boundary mode adds only sched_entry_tp and sched_exit_tp with two dedicated maps, and uses private admitted-worker identity plus birth validation. Pre-arm thread entry and exit are outside this boundary channel.

Run a boundary conformance case, then a lifecycle/boundary primer and four pairs in order lifecycle/boundary, boundary/lifecycle, lifecycle/boundary, boundary/lifecycle. This estimates incremental observer cost over the original lifecycle collector. Retain each case and stop on the first invalid case. Use the existing paired aggregation and keep the original benchmark gates. No performance pass threshold.

Require the original CLR callback and remote-wake evidence, held identities, zero lifecycle loss or recursion misses, and clean reap. Additional ledger: 1024 x 48 bytes, maximum 16 admitted workers. Require exact terminal accounting, second read and zero reported losses/faults/misses. Pair entries and exits by generation and reservation order. Require a newborn prefix and at least one returned switch invocation for the named managed callback. Preserve other prefixes, unreturned retired entries and clock inversions. Scope is software callbacks, not physical CPU or GC attribution. Report no-switch, preempt and CPU endpoint changes as observed coverage only.

Freeze protocol, supervisor, source, artifact hashes and mode order before execution. Each case has a 40 second launcher deadline and an actor deadline of 30 seconds. The same runner, binaries and source must match after each case. Keep raw originals and mask kernel address literals in published verifier logs. #3 stays Blocked and #20 tracking metadata remains as recorded.
