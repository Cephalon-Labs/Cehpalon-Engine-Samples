# CLR ThreadPool scheduler fixture under ADR0030

Date 2026-11-06. Use the pinned WSL kernel and BTF, .NET SDK 11.0.100-rc.3.26522.148 and runtime 11.0.0-rc.3.26522.148. Build the four locked fixture sources on the guest filesystem with the existing native SDK and an empty restore source. Freeze source, commands, runtime and build artifacts, and BPF templates before execution. Bind the PID namespace inside the single Linux supervisor. Use a fresh ordinary UID/GID 1000 process, CPU 0 leader and CPU 1 worker per case. The same executable, files, environment and commands apply in both modes. CLR runtime policies stay at their defaults.

## Native conformance

Run one instrumented conformance case before the overhead series. The held CLR actor reports zero ThreadPool workers before the first enqueue. Bind a stable cohort of at most 16 owned pre-arm TIDs. Prove the leader's acknowledgement with the named gettid hook and a negative controller marker. Use the pinned thread pidfd flag for each sibling and verify its live local TID, group, start time and credentials before map seeding. Recheck the cohort and require zero counters immediately before release. Pre-arm TIDs can parent a new generation. Their earlier lifetimes are outside the ledger.

Use the same task admission, split switch hooks, exec guard and terminal free accounting as the multiworker fixture. Bound the experiment to at most 16 new generations and 2,048 publications. Retain only sanitized rows and fixed counters. The independent CLR receipt comes from a real ThreadPool callback with its native gettid, managed identity and timing bracket. Require one admitted generation matching that TID, with birth and first switch before the callback, a verified blocked pipe read on CPU 1, and first waking after the oracle from CPU 0 to CPU 1 within the ping bracket. Require the first resumed switch on CPU 1 and the same worker identity still held after the callback's work. Verify every admitted lifetime through exit, terminal switch and free with a two-second tail after process reap. This is process teardown. Retirement through the idle policy is a separate case. Classify other admitted generations as auxiliary unless independent evidence identifies their role.

Reject overflow, admission faults, missing lifecycle evidence, changed terminal reads or any reported recursion miss. Retain the complete first detached ledger and second hash and counters. Compare the held post-work task snapshot to pre-arm or admitted identities. The bounded observations establish the joined callback and admitted generations. Short-lived births from an unbound parent remain outside the completeness claim.

## Descriptive overhead series

After conformance passes, execute the whole fixed series sequentially. One fresh OFF/ON primer pair precedes four fresh measured pairs in this order: OFF/ON, ON/OFF, OFF/ON, ON/OFF. OFF performs the same actor controls, pidfd binding and blocked-read verification with no BPF programs or maps. ON adds the collector and must pass the same native lifecycle gate. Run the same 64 pipe round trips and 4,096 arithmetic operations with checksum `4fcd3a1dd438d325` in every process. Release, wait and reap in both modes. Keep actor CLOCK_MONOTONIC and Stopwatch readings plus process CPU readings. Keep controller preparation, command and cleanup clocks separate.

The primary interval is the actor's fixed pipe loop. Report each signed ON minus OFF delta and relative change, plus median and range of all four measured pairs. Report full actor work separately because it includes park control. Preserve both primers, all observations and any failed attempts. Stop on an invalid case and retain the incomplete series. There is no speedup, overhead acceptance threshold or original benchmark qualification from these shared-WSL observations.
