# Multiworker scheduler fixture under ADR0030

Date 2026-11-06. Extend the [one-worker fixture](dynamic-scheduler-active-fixture.md) on the same pinned WSL release and raw BTF. The root controller binds the live PID namespace in the same Linux invocation, checks the shared monotonic namespace and runs one fresh UID/GID 1000 actor per case. CPU 0 runs the leader and emits the controlled pipe wake. CPU 1 runs the parked workers. Freeze the commands, protocol, source and bytecode templates before running. Only live map FDs and the same-execution namespace immediate may relocate.

Run the fixed-capacity loss negative first, then a fresh positive only if it passes. Both cases start with the previously proven named owner acknowledgement, close that hook, and arm the lifecycle hooks before releasing the actor. Split the raw switch into incoming and outgoing programs on the same named tracepoint so a switch between two owned workers can be observed on both sides. Check every raw link name and cookie and require zero reported recursion misses. An ordinary process fork before thread birth must leave the counters zero.

The leader creates worker A, and A creates B. Hold both in verified empty-pipe reads. Wake A from CPU 0, join it and require its kernel free completion and proc disappearance within two seconds of join. Verify B is still blocked, then wake it from CPU 0 and require the same retirement proof. Only after the two frees may the leader create C. Give C a fresh pipe, wake it from CPU 0 and verify its complete retirement.

The private preallocated hash holds at most four entries. It keys on the raw task pointer, which serves only as a lookup key until a match. Compare the live birth field to the cached birth field after membership. Admission requires a same-group `CLONE_THREAD` child of the seeded leader or an active enrolled worker. Validate the exact PID layout and namespace inode at birth. Assign three monotonic generation ordinals and record the parent generation. Mark exit before publication, retain the entry through terminal switch and copy cached IDs before deletion at free. Record completed free only after successful deletion and publication accounting. The owned exec guard faults before identity mutation. Keep pointer keys, birth fields and foreign identities out of the ledger. Use a fixed 512-slot array of 40-byte rows. The negative allows one publication and must keep A's birth, demonstrate nonzero capacity loss and count all three admissions and completed frees. The positive allows all 512 slots and must account for every publication, with zero loss or faults and exactly three admitted and freed generations. For each worker require the complete one-worker lifecycle, controlled cross-CPU waking within its own write bracket, the first resumed switch on CPU 1, distinct IDs while live, and matching kernel and actor local TIDs. A's first switch must precede B's birth, A's free must precede B's wake, and B's free must precede C's launch. Require identical terminal counts and ledgers across detached reads. Retain the second count snapshot and second ledger SHA-256 as well as the first full ledger. Close all 28 owned descriptors and reap the actor. Keep rejected attempts.

Offline cases cover numeric TID reuse after free, collision during overlap, and stale generation rejection. Native readmission of C proves a new generation after deletion. Actual pointer or TID reuse requires direct observation. This run is synthetic and does not qualify Roslyn, quantify instrumentation overhead or change the original benchmark.
