## Fixed staged case scope

One ordinary UID/GID1000 controller process and four precreated worker threads per fresh session (five leased native TIDs, bounded max16). Each live actor is mapped in the same execution with the reviewed task-attached syscall-specific gettid bootstrap before constructing global S. Retain every independent proc UID/GID/capability/image/starttime/namespace lease and every recheck/environment observation; no inferred or cross-boot identity. Initial/final scheduler states remain unknown where not fully observed.

All eight scheduler events have one initially-disabled FD on every declared online CPU (max32,256FDs). Pin exact raw ABI, CLOCK_MONOTONIC attributes, CLOEXEC, read-format23 and forward nonoverwrite rings with verified lock-free acquire/release head/tail. Apply/ACK every payload-side filter and validate all leases before any enable; then release actors after the last enable. Switch uses prev/next PID, fork parent/child PID, other events target pid, never common_pid. No generic perf sideband or unfiltered host trace. Counterparty/header/comm metadata inherent in matched events remains retained and disclosed.

1. Negative overflow FIRST: one data page/FD, fixed10,000 two-worker handshakes pinned to first permitted CPU, consumer withheld250ms with fixed max5second pressure deadline. Require actual nonzero terminal per-FD PERF_FORMAT_LOST to demonstrate rejection; no final LOST record is required. A zero-loss result is inconclusive and does not authorize adaptive pressure/favorable repeat. Close/join every negative resource before a fresh positive session.
2. Positive:64data pages/FD, max65MiB mappings across32CPUs including metadata,1ms drain cadence, fixed park/wake/yield/running/migration/armed-sacrifice and controlled nonmember-fork phases to be enumerated in the final execution declaration before launch. Fixed2second post-join RCU tail; missing free remains unknown/failure, not a favorable-repeat reason. Require at least two permitted CPUs for migration. Per-attempt retained output cap256MiB and bounded deadlines/cleanup must be frozen before launch.

Forward ring head-tail overrun is an invariant failure, not expected negative overflow. Positive requires zero terminal loss/throttle/decoder errors, stable final drain/counters and conservative per-FD count==parsedSAMPLE; this is an observed gate, not a universal kernel equation. Count can increment on paths without a published sample. Do not sum emitted LOST and terminal lost_samples as independent loss. Retain all errors, raw bytes, accounting and state/clock uncertainty.

Before the first execution, strengthen positive CPU-wide FD accounting to require0<time_running==time_enabled. Exact kernel accounting permits legitimate inactive/setup/hotplug gaps, so this is a conservative observed rejection gate, not an assertion that every mismatch is a code bug. Equality does not prove upstream event delivery, uninterrupted wall-clock coverage or host CPU service. Do not apply it to per-task mapping FDs or interpret either field as actor CPU time.

## Explicit unexercised and lifetime gates

Precreated/mapped S cannot positively exercise owned sched_wakeup_new or captured child-side birth after arming. The positive controlled nonmember child is forked from a leased controller solely to test parent-side fork delivery and nonmember exclusion; never add its ID to S. Its new-wake should be filtered out. Owned wakeup_new delivery remains UNEXERCISED/UNKNOWN, so no all-eight positive-delivery or dynamic Roslyn readiness claim follows even if all FD/filter calls and other exercised gates pass.

Holding a pidfd does not reserve the numeric PID after free_pid removes it from IDR. Retain sacrificial exit/join/end brackets and fixed RCU-tail raw records; post-end matches remain unassigned until their declared lifecycle observation is resolved. Matching fork/newwake reuse poisons that numeric generation; no automatic ownership expansion. Preserve initial/final/tied/missing transitions and possible upstream gaps. Filters match bounded numbers, not immutable task lifetimes; possible post-end reused-ID metadata and existing counterparty metadata are explicit limits, not owned-work attribution.

Require actual owned cleanup, stage/phase counts, collector CPU/cadence/buffer/output resources, positive/negative filter evidence, precise state/preempt/dynamic-string decoding and marker/session-clock ordering. Static observed chains do not establish useful compiler work, host-vCPU availability, GC cause or dynamic ThreadPool coverage. Preserve every failed/preparation/source/fixture/raw attempt; corrections require a separately stated frozen attempt, no selecting/stitching/favorable reruns.
