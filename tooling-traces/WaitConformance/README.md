# Synthetic same-process wait collector conformance

Linux x64 only, pinned net11.0 SDK. This fixture is not an Engine workload, benchmark, provider test or performance acceptance. It creates one joined CPU worker, waits on an intentionally unsignalled managed event (80ms timeout), executes one direct SYS_futex202/FUTEX_WAIT_PRIVATE128 relative80ms expecting ETIMEDOUT110, verifies4096known file bytes, does bounded CPU/allocation work and explicitly forces GC **only for synthetic collector verification**.

Seven main-native-TID spans: startup, cpu, managed-wait, native-futex-wait, explicit-gc-conformance-only, file-write-read, result. The worker never calls the single-thread diagnostic logger. Sidecar records repeated post-body UTC reads bracketed by Stopwatch in addition to startup anchor and EventPipe marker brackets; UTC precision is100ns. Preserve clock incompatibility and all partial/loss/pairing flags rather than treating them as zero.

DiagnosticSupport.cs is generated by applying tools/prepare_tooling_wait_driver.py clock_support() to the original diagnostic helper support source. Build with the committed SDK/NuGet inputs and locked restore. Actual conformance requires native+managed positive events, exact semantics/owned lifecycle/known IO and conditional clock checks, not an80ms acceptance budget. No forced GC, extra warmup, runtime flags or fixture instrumentation is added to the original benchmark.
