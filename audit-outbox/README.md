# Optional PostgreSQL audit transaction/outbox consumer

Experimental local proof using existing Core/Composition, generated HTTP/GraphQL gateways and a separately generated protected relay gateway. The project alone references pinned Npgsql10.0.3; the prior security-api consumer and its651-case corpus keep their package graph and default behavior. Select the trusted `IEntityTrailIntegration` sample hook to activate this provider against the same immutable tenant registry before credentials/listener creation. Provider/history handler factories stay lazy. The hook is sample integration, not a new engine authorization shortcut.

Each project chooses Disabled/MetadataOnly/ChangedFields/BeforeAfterSnapshots and separately chooses whether to activate/invoke its relay. Enabled updates use one physical Npgsql connection/transaction for the domain change and frozen redacted outbox record. The callback receives only a tenant-bound domain session, not commit/rollback methods. Session methods reject foreign tenants and use-after-disposal. This bounded sample supports entity.update; unsupported create/delete routes reject before SQL acquisition. Disabled auditing still performs ordinary business SQL work while outbox provider activation/staging/relay work stays off. All modules off has no provider factory, connection, handler or listener work.

A successful business response means domain plus outbox committed, not that final audit history is delivered. The explicitly invoked relay resolves its dedicated service identity/membership/policy freshly; ordinary write/history permission and disposed writer contexts do not grant relay rights. Claims use SKIP LOCKED and tenant/receipt/lease/expiry fences. Identical frozen payload replay is idempotent in the final sink; a conflicting payload for the same tenant/receipt fails. A failure after sink append but before acknowledgement can replay; this is at-least-once delivery with sink deduplication, not distributed exactly-once. Pending rows remain for later authorized processing; no background worker, automatic retry, renewal, drop or retention policy is installed.

Final-sink history reads use the existing checked `TenantChangeAuditHistoryReader`, distinct field-history permission and current project projection. Queued records do not appear before relay. Capture policy is frozen in the outbox; tightening read policy can hide captured values, while richer read modes cannot recreate missing/redacted data. Physical outbox and sink payloads are explicitly checked for redacted source secrets. The closed provider codec has symmetric finite bounds and preserves typed missing/null/boolean/decimal/redacted values without serializing arbitrary objects or identity sessions.

`tools/verify_audit_outbox.py` requires a separately owned fixture plus private `.env` connection file, initializes a new schema for each attempt, freezes actual sources before SDK work and retains every failed output. It never provisions or mutates an arbitrary external database. The declared fixture is an official PostgreSQL18 immutable image with a private retained volume and loopback-only published port. Windows.NET Npgsql reaches the WSL container through an owned Windows loopback/binary-stdio proxy; WSL.NET connects directly to WSL loopback. This is not native Windows PostgreSQL support. Private connection files, data volumes, keys, protocol bytes and credentials must not be exported.

The verifier runs the provider corpus, exits a writer process, restarts only the named owned server, then launches a separate reader/relay process against the same schema. It records actual SQL version and fsync/synchronous_commit/full_page_writes without changing them. Reopen/restart is not physical power-loss, all-provider, performance, durability-policy or production certification. Original benchmark gates and #3 Blocked remain unchanged.


## Optional tenant outbox status

The selected `TenantChangeAuditOutboxStatusReader` uses a separate fresh `audit-outbox/tenant/inspect` context. Status is count/timestamp metadata only: pending, available (including expired claims), actively claimed, expired claims, provider-acknowledged delivered, oldest pending database enqueue timestamp and provider observation time. A materialized one-statement PostgreSQL clock and MVCC aggregate keep the partition coherent; this is not a claim of client freshness, a linearizable wall-clock observation, queue repair or relay authority.

The status query does not select payloads/receipts/principals and performs no claim, acknowledgement, release, sink append or domain mutation. Disabling status skips its source factory/work. The ordinary transaction/relay/history paths remain independent. A sink row after acknowledgement loss can coexist with pending1/delivered0; status does not equate sink presence with delivery acknowledgement. New owned schemas add database-generated `enqueued_at`; no historical fixture schema migration is run.

The additional `StatusChecks` corpus runs separately after the original34 cases, with original3 process/restart cases retained. It covers exact physical oldest timestamps and transitions, permissions/tenant partitions, post-query and actual lock-blocked PostgreSQL cancellation, and independently scheduled reads. SQL lock/expiry controls are owned test fixtures, not Engine runtime APIs. No metrics listener/background worker, payload endpoint, provider freshness or production qualification is installed.

## Optional cooperative relay budget

Projects can explicitly select `TenantChangeAuditOutboxRelay.ActivateWithBudget(true, relayTimeout, sourceFactory, sinkFactory, leaseDuration)` separately from the authority lease. A null budget preserves legacy work tokens and faults; Disabled skips bounds and factory work. Configured positive budgets up to one minute request cancellation through the same linked claim/sink/ack token, while release retains its independent five-second token. Uncooperative work is awaited; a budget does not promise forced termination or a completion latency. Late known leases are released. Caller/private cancellation classification uses observed signals, with caller precedence, rather than proving what caused a provider exit.

The added24-case corpus keeps the prior34 outbox,23 status and3 restart cases separate. Actual provider deadline controls tag a new instance of the same PostgreSQL adapter with an owned application name and observe its exact backend in a `Lock` wait before expiry: ACCESS EXCLUSIVE table locking blocks the real SKIP LOCKED claim statement; a row lock blocks real acknowledgement. Owned tasks are joined and backend quiescence checked before reuse. Other late/fault controls are explicitly delegate wrappers around or before SQL. Fresh authority, manual replay, idempotent sink and stale-lease fences preserve delivery uncertainty; a committed sink or acknowledgement is not rolled back by timeout. No retry, background relay, schema change, provider upgrade, original benchmark qualification or native Windows PostgreSQL claim is added.

## Bounded manual drain

The separate generated `outbox.drain` gateway calls `DrainAsync` through its own fresh checked service operation, action `relay`, rather than inheriting an ordinary relay or inspect grant. That separate operation grant is this consumer's policy; portable `DrainAsync` requires a live matching audit-outbox/tenant/relay scope rather than a particular operation ID. Projects choose finite caps up to16 batches,2048 observed acknowledgements and128 records per batch. Positive underfilled batches continue; zero acknowledgements stop with `NoProgress`, which does not establish a globally empty queue when other claims or writers exist. Record limits take precedence over tied batch limits. Scope rechecks inside one operation do not resolve identity providers again.

The new24-case actual PostgreSQL corpus retains the earlier84 cases separately. It covers actual partition/remaining caps, independently produced work after underfill, active claims with pending rows, partial and uncertain acknowledgements, independent cleanup, fail-fast poison behavior, fresh manual replay/dedup, and exact tenant/operation grants. Fault, budget and deterministic post-count clock controls are labeled wrappers; they do not measure physical timeout latency. Prior foreign-tenant partial relay exceptions are retained as original failures without importing their acknowledgement metadata into a new drain. There is no new status/history query, retry, outer release, scheduling/background service, overall timer, schema change or provider upgrade. Each selected cooperative budget still belongs to one batch.
