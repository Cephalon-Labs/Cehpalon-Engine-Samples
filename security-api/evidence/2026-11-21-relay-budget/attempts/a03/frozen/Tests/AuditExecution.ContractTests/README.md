# Optional audit execution contracts

Experimental local contracts for `TenantChangeAuditRecorder.ExecuteAsync`: ordinary pre-invocation failures have no mutation callback; every failure after invocation starts conservatively reports `MayHaveCommitted`. A returned receipt's completion uses the existing private write deadline and live checked context independently of pending caller cancellation; caller cancellation is checked before returning the result. Invalid receipts, expired contexts and provider failures can still prevent append. The deadline bounds cooperative sinks, not an unresponsive provider that ignores cancellation. The existing `Prepare`/`CompleteAsync(callerToken)` behavior is unchanged.

The trusted mutation is invoked and its ValueTask consumed once per call; required recording is awaited before the result is returned. The envelope has immutable properties but does not freeze a mutable business result object. Callbacks that throw after partial effects cannot supply a receipt, so the helper cannot invent an audit record. New calls can invoke another mutation and are not an idempotent retry protocol. Persistence remains separate from mutation: no transaction, rollback, exactly-once, outbox or durable-provider/production qualification is established. Disabled modules do not activate a recorder; the helper does not change plain Core/codegen authority.

Run with the pinned SDK, locked restore, Release/warnings-as-errors and a new `--output=<path>`; retain all source and raw attempts. Full cross-host verification is owned by the integrating root.
