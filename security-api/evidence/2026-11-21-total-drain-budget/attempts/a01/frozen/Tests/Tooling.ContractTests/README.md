# Experimental portable tooling contract checks

This console suite exercises Engine issue #20's bounded portable CLI through
`CliApplication.Run`. It checks strict usage/exit codes, invalid configuration,
deterministic generated bytes, filesystem boundaries, and non-destructive failure
handling. It creates isolated temporary fixtures and retains their paths in the
JSON result for investigation. It never starts generated services or builds the
generated application.

The fixed scaffold contains nine files. An internal filesystem interface wraps
the production physical writer/mover to exercise a failure before and after each
file write, a failed publication, and a destination created by another writer
immediately before atomic publication. The checks require owned staging cleanup
and byte-preservation of unrelated files. There are no public fault-injection
flags or environment switches in the product.

The separate Samples proof must restore, build and execute actual generated
consumers; this suite is not a substitute for that compiler/runtime evidence.
It also does not establish real API/GraphQL/Worker/provider behavior, supported
Windows qualification, full tooling acceptance or benchmark results.

Use the repository-pinned private SDK and package cache:

```text
dotnet restore Tests/Tooling.ContractTests/Tooling.ContractTests.csproj --locked-mode --configfile Tests/Tooling.ContractTests/NuGet.Config
dotnet run --project Tests/Tooling.ContractTests/Tooling.ContractTests.csproj -c Release --no-restore -- --output=.local/tooling-contracts.json
```

Directory-symlink tests require the ability to create symbolic links on the
current host. A privilege failure is reported as a failed check, not silently
skipped or counted as path-isolation proof. Test-generated roots are under the
OS temporary directory or an owned new directory under this checkout's `.local`.
Negative output-boundary cases request a fresh nonexistent path under the
three named checkout fixtures and verify refusal without creating it. Each fixture
copies only the seventeen required source inputs, creates a dummy `.git` marker
and Docs/Samples sibling directories with dummy `.git` markers; it does not require other repository
checkouts or claim git-attested provenance. Windows-only extended-path alias
checks supplement cross-host lexical rejection of device namespaces. Actual
source-checkout and generated compiler proof remains separate.
An additional regression distinguishes the actual checkout from a same-named
outer runner directory, preserving allowed `.local` output on hosted runners.

The Small API subset adds exact fourteen-file generation/determinism, pure validation
of four profile configurations, unsupported capability rejection, all twenty-eight
before/after file-write fault positions and a publication collision. Real HTTPS,
JWT and tenant checks run in the separate generated-consumer Samples verifier.
