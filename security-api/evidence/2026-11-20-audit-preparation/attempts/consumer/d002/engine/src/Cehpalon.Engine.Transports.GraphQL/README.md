# Experimental GraphQL HTTP adapter

This opt-in adapter targets the locked .NET 11 RC3 / HotChocolate 16.7.1 profile. It is not an IdP, provider, supported-Windows or production qualification. The HTTP adapter project has no dependency on this project.

Create a `GraphQLOperationCatalog.Builder`, add explicitly named typed query/mutation fields using the same `OperationBinding<TRequest,TResponse>` used by HTTP, then `Build()`. The immutable catalog requires a query field, rejects duplicate fields and supports at most 256 fields. Its construction registers no services, executes no validators and creates no business handlers. Public class/record request and response DTOs form the GraphQL contract; HotChocolate infers their fields. No handler or operation discovery takes place. Treat DTO field changes as schema changes.

Only when the compiled composition plan enables GraphQL call `services.AddCehpalonGraphQL(catalog)` and `endpoints.MapCehpalonGraphQL("/graphql")`. Do not call either method for a disabled module: the adapter does not itself read configuration or suppress eager work already registered by a caller. The host must prove disabled registration, schema/executor, endpoint and background work remain zero across its own lifecycle.

Each field has one required `input` argument. Its server-owned binding fixes the operation ID. The shared pure typed validator runs before resolving the host-owned `ITransportOperationDispatcher`. Configure that bridge to authenticate with the established protocol implementation and route protected calls through fresh `TenantOperationDispatcher` authority checks. `IsAuthenticated`, `HttpContext`, arbitrary claims and Core correlation metadata do not themselves validate a JWT or grant tenant membership. Host authentication middleware must run before the endpoint. The adapter requires an authenticated principal and returns HTTP 401 before parsing an anonymous request; the resolver checks again before dispatch. The host must not create that principal from unvalidated caller headers.

The bounded transport is POST JSON only, with a 16 KiB byte limit including unknown-length/chunked requests, JSON depth 32, unique property names and valid Unicode. Supported envelope members are `query`, optional object/null `variables`, and optional string/null `operationName`. Arrays, variable batches, unknown envelope members, persisted-query extensions, multipart uploads, GET requests, schema download, IDE and WebSocket routes are unsupported. No subscriptions are registered. Incremental `@defer`/`@stream` is disabled. Execution depth is capped at 8 and enforced field/type costs at 1000 each, including aliases and fragments. `__schema` and `__type` introspection are disabled; standard `__typename` remains available. Schema details in validation errors are normal GraphQL behavior, so this is not schema secrecy.

Application success returns typed data. An intentional `OperationError` returns GraphQL `errors[].extensions.code`; HTTP 200 for a successfully executed GraphQL operation containing a semantic error is deliberately different from REST's status mapping. Shared typed validation emits generic `validation.failed`, and `access.denied` and `operation.capacity_exceeded` each use a fixed generic message. Other intentional business error codes/messages are trusted application contracts and must be safe to disclose. Protocol parsing/coercion/complexity errors retain HotChocolate's protocol codes and status behavior; malformed envelopes are HTTP 400, oversized bodies 413 and unsupported content types 415. Unexpected host exceptions, including `GraphQLException` and cancellation unrelated to the request, emit generic `internal.error` without exception details.

The dispatcher receives cancellation linked from the HTTP request and GraphQL resolver. The adapter checks cancellation before and after the dispatcher await. A canceled invocation is not a rollback promise for business effects already performed. The host owns business/resource lifetimes and concurrency/transaction behavior.

`Tests/GraphQL.ContractTests` uses real loopback Kestrel HTTP with a finite trusted principal fixture. It tests mapping, immutable catalog, validation, safe errors, byte limits, malformed/ambiguous bodies, schema exposure, depth/cost, cancellation and unsupported protocol features. It does not validate real identity tokens, TLS or tenant sources; the separate consumer provides those scoped proofs. Windows local observations do not clear #3.

Implementation facts checked against the actual 16.7.1 package XML and compiled APIs: `DisableIntrospection(true)` (the newer online `AllowIntrospection(false)` name is not available in this lock), `AddMaxExecutionDepthRule(8)`, `ModifyCostOptions`, `AllowedBatching.None`, and `MapGraphQLHttp`.
